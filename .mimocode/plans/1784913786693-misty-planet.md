# Knowledge Engine - Implementation Plan

## Overview

Build a Python CLI-based Knowledge Engine that maintains a structured, offline-first knowledge system with local storage, file ingestion, cascading query pipeline, and cloud sync capability.

## Architecture

```
┌─────────────────────────────────────────────────────┐
│                   CLI Layer (Typer)                  │
├─────────────────────────────────────────────────────┤
│              Query Engine (Pipeline)                 │
│  Memory → Cache → Local DB → Vector DB → Cloud → Web│
├─────────────────────────────────────────────────────┤
│              Storage Layer                           │
│  SQLite (metadata) + ChromaDB (vectors) + FS (cache)│
├─────────────────────────────────────────────────────┤
│              Ingestion Engine                        │
│  PDF, DOCX, TXT, MD, HTML, JSON, CSV, Code, etc.   │
├─────────────────────────────────────────────────────┤
│              Embeddings (sentence-transformers)      │
├─────────────────────────────────────────────────────┤
│              Network Detection                       │
└─────────────────────────────────────────────────────┘
```

## Tech Stack

| Component | Library | Rationale |
|-----------|---------|-----------|
| CLI | `typer` + `rich` | Clean CLI with rich output formatting |
| Vector DB | `chromadb` | Embedded, zero-config, local-first |
| Metadata DB | `sqlite3` (stdlib) | Structured queries, no extra deps |
| Embeddings | `sentence-transformers` | Local inference, no API keys needed |
| PDF parsing | `pymupdf` (fitz) | Fast, reliable PDF extraction |
| DOCX parsing | `python-docx` | Standard Word doc support |
| HTML parsing | `beautifulsoup4` + `readability-lxml` | Clean text extraction from HTML |
| Code parsing | `tree-sitter` | Multi-language AST parsing for code similarity |
| Network | `requests` + `netifaces` | HTTP + interface detection |
| Config | `pydantic` + `tomllib` | Type-safe config with TOML files |
| Caching | `shelve` (stdlib) | Simple key-value local cache |
| Packaging | `pyproject.toml` + `hatch` | Modern Python packaging |

## Implementation Phases

### Phase 1: Foundation (Core Models + Storage)
**Files:** `config.py`, `core/models.py`, `storage/metadata.py`, `storage/vector.py`, `storage/cache.py`

1. Define Pydantic models for:
   - `KnowledgeEntry` (id, content, summary, tags, embeddings, source, confidence, relationships, timestamps)
   - `QueryResult` (entry, score, source_layer, explanation)
   - `IngestionResult` (source_path, chunks_created, knowledge_entries, errors)
   - `NetworkState` (status enum, interfaces, capabilities)
2. Implement SQLite metadata store with schema:
   - `knowledge` table (id, content, summary, tags JSON, source_path, confidence, created_at, updated_at)
   - `relationships` table (source_id, target_id, relationship_type, weight)
   - `conversations` table (id, session_id, role, content, timestamp)
   - `logs` table (id, event_type, data JSON, timestamp)
3. Implement ChromaDB vector store wrapper
4. Implement local shelve cache

### Phase 2: Embeddings + Ingestion
**Files:** `embeddings/model.py`, `ingestion/*.py`

1. Wrap `sentence-transformers` with lazy loading and configurable model
2. Implement base `Ingestor` protocol with `ingest(path) -> list[KnowledgeEntry]`
3. Implement ingestors:
   - PDF: pymupdf text extraction + page metadata
   - DOCX: python-docx paragraph extraction + structure
   - Text/Markdown: direct read + heading detection
   - HTML: readability-lxml + metadata extraction
   - JSON/CSV: structured parsing with field extraction
   - Code: tree-sitter AST extraction for function/class docs
   - Archives: ZIP/EPUB extraction with recursive ingestion
4. Implement chunking strategy (configurable chunk size + overlap)

### Phase 3: Query Pipeline
**Files:** `core/pipeline.py`, `retrieval/*.py`

1. Implement cascading query pipeline:
   - Layer 1: Runtime memory (session context)
   - Layer 2: Local cache (shelve)
   - Layer 3: Local metadata DB (SQLite FTS)
   - Layer 4: Local vector DB (ChromaDB)
   - Layer 5: Cloud vector DB (if configured + online)
   - Layer 6: Internet search (if enabled + user permission)
2. Implement retrieval strategies:
   - Semantic: vector similarity search
   - Keyword: SQLite FTS5 full-text search
   - Hybrid: reciprocal rank fusion of semantic + keyword
   - Code similarity: AST-based code matching
   - Metadata: tag/source/date filtering
   - Time: recency-weighted search
   - Relationship: graph traversal from known entries
3. Implement confidence scoring and result ranking

### Phase 4: Network Detection
**Files:** `core/network.py`

1. Detect network state (offline/WiFi/cellular/limited/poor)
2. Implement `netifaces`-based interface enumeration
3. Implement connectivity check (DNS + HTTP probe)
4. Implement connection quality estimation (latency + bandwidth probe)
5. Expose as context manager for pipeline decisions

### Phase 5: Learning + Self-Knowledge
**Files:** `core/learning.py`

1. Post-task knowledge extraction:
   - Extract key facts from completed tasks
   - Generate embeddings + summaries + tags
   - Store relationships between entries
2. Knowledge graph maintenance:
   - Auto-link related entries (shared tags, co-occurrence)
   - Decay old relationships
3. Self-study of imported materials:
   - Extract concepts, definitions, examples
   - Build knowledge graph from documents
   - Generate study summaries

### Phase 6: Cloud Sync
**Files:** `storage/sync.py`

1. Abstract `CloudProvider` interface with methods:
   - `push(entries)`, `pull(query)`, `sync()`, `status()`
2. Implement local mock for development
3. Implement sync protocol:
   - User permission gating
   - Conflict resolution (last-write-wins + manual)
   - Incremental sync (delta only)
   - Encryption in transit

### Phase 7: CLI
**Files:** `cli.py`

Commands:
```
ke init                    # Initialize knowledge base
ke ingest <path>           # Ingest file/directory
ke query <text>            # Search knowledge base
ke query --mode <mode>     # Search with specific retrieval mode
ke list                    # List all entries
ke show <id>               # Show entry details
ke export                  # Export knowledge base
ke import <file>           # Import knowledge base
ke sync                    # Sync with cloud (if configured)
ke config                  # Show/edit configuration
ke status                  # Show system status (DB size, network, etc.)
ke learn                   # Trigger learning from session
ke relationships <id>      # Show entry relationships
```

### Phase 8: Testing
**Files:** `tests/*.py`

1. Unit tests for each storage backend
2. Unit tests for each ingestion format
3. Integration tests for query pipeline
4. CLI smoke tests
5. Test fixtures with sample files (PDF, DOCX, code, etc.)

## Configuration

```toml
# config/default.toml
[engine]
version = "1.0.0"
data_dir = "~/.knowledge-engine"

[embeddings]
model_name = "all-MiniLM-L6-v2"
device = "cpu"
batch_size = 32

[storage]
vector_db_path = "~/.knowledge-engine/vectors"
metadata_db_path = "~/.knowledge-engine/metadata.db"
cache_path = "~/.knowledge-engine/cache"

[chunking]
strategy = "fixed"  # fixed | semantic | sentence
chunk_size = 512
chunk_overlap = 64

[retrieval]
default_mode = "hybrid"
max_results = 10
min_score = 0.3
enable_relationships = true

[query.pipeline]
layers = ["cache", "metadata", "vector", "cloud", "internet"]
cloud_enabled = false
internet_enabled = false
internet_requires_permission = true

[sync]
provider = "local"  # local | s3 | gcs | custom
remote_url = ""

[network]
check_interval = 30
probes = ["dns", "http"]
quality_threshold_latency_ms = 500
```

## Verification Plan

1. **Unit tests**: `pytest tests/` - all storage, ingestion, retrieval tests pass
2. **CLI smoke test**:
   ```bash
   ke init
   ke ingest tests/fixtures/sample.pdf
   ke ingest tests/fixtures/sample.py
   ke query "what is the main function"
   ke status
   ```
3. **Pipeline test**: Verify cascading fallback (offline → local only)
4. **Ingestion test**: Process each file format and verify entries created
5. **Retrieval test**: Query with each mode and verify results ranked correctly
6. **Network test**: Mock offline state, verify pipeline skips cloud/internet layers
7. **Config test**: Override defaults via config.toml, verify behavior changes

## Key Design Decisions

1. **Local-first**: All core features work offline. Cloud/internet are optional layers.
2. **Embedded DBs**: ChromaDB + SQLite run in-process, no server needed.
3. **Lazy loading**: Embedding model loaded on first use, not at startup.
4. **Pluggable ingestors**: New file formats added by implementing the Ingestor protocol.
5. **Confidence tracking**: Every entry and result carries a confidence score.
6. **Permission-gated sync**: Cloud sync never happens without explicit user consent.
